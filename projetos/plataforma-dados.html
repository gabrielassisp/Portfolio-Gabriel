Explorar transformação e qualidade

Uma fonte, um grão explícito

A Silver mantém 400 negócios, 800 eventos de histórico, 600 chats e 30 registros de anúncios. Quatro registros inválidos são separados e dez versões duplicadas são removidas. A maior versão ganha; o número de ingestão desempata.

Modelo dimensional mínimo

Gold contém uma linha por negócio na fato, uma por responsável na dimensão e uma por dia nas métricas. As fontes são agregadas antes dos joins para evitar multiplicação dos valores por histórico ou chats.

select deal_id,owner_id,business_date,status,amount_cents,run_id
from {{ ref('silver_deals') }}

Testes

Os 22 testes dbt verificam unicidade, campos obrigatórios, relações entre tabelas, contagens do cenário e seleção da versão mais recente.

Reexecução e recuperação verificáveis

A ingestão substitui o snapshot em uma transação. A verificação repetiu a carga sem mudar conteúdo ou contagem, injetou uma falha após 100 registros e comprovou o rollback. O histórico registrou a falha.

Executar e entender os limites
cd platform-demo
docker compose run --build --rm pipeline
docker compose run --rm pipeline python verify_recovery.py

Postgres isolado, sem portas publicadas no computador, rede e volume próprios. A configuração usa uma thread dbt, 256 MiB para o banco e 512 MiB para o runner. As senhas no Compose são exemplos locais descartáveis.

O laboratório não usa dados nem regras internas de produção. O snapshot não é uma carga incremental, e não há transação global entre a ingestão e todos os modelos dbt. O histórico SQL registra ingestões; o resultado completo, incluindo dbt, fica nos artefatos.

Relação com a plataforma privada

A implementação profissional integra Zoho, Huggy e Meta, com execução via n8n e ETL Monitor. O laboratório público exercita padrões semelhantes com dados fictícios; não é uma cópia nem oferece todas as capacidades do ambiente privado.
