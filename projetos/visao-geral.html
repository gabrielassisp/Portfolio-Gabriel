Plataforma de dados

Integrar fontes de CRM, atendimento e marketing e organizar transformações com dependências explícitas.

Explorar projeto ↗Demo Postgres + dbt no GitHub ↗
Arquitetura, competências e resultados
APIs de negócio → Python → PostgreSQL → dbt → modelos analíticos

O que a implementação demonstra

  • Quatro fluxos: negócios e histórico Zoho, chats Huggy e anúncios Meta.
  • Ingestão Python conectada a seletores dbt específicos por fluxo.
  • Camadas Bronze, Silver e Gold e validações nos processos.

Resultado e evidência

A CI pública de 02/11/2026 aprovou Docker Compose, dbt, recuperação e incremental (400 → 401 negócios, com reexecução sem duplicatas). É uma execução específica, não média nem SLA.

O código de produção é privado. O laboratório público inclui uma versão mínima Postgres + dbt + Docker Compose com fontes fictícias. Não reproduz todas as capacidades nem as regras internas da plataforma.

Brazil Economic Pipeline

Disponibilizar indicadores públicos em uma implementação cloud pequena e reproduzível.

Explorar projeto ↗Código cloud no GitHub ↗
Arquitetura, competências e resultados
IBGE / BCB / World Bank → Python → BigQuery Bronze → dbt Silver / Gold

O que a implementação demonstra

  • Validação antes do upload: fontes ausentes, duplicatas e valores não finitos interrompem a carga.
  • Particionamento pela data de ingestão e clustering por fonte, indicador e referência.
  • Quatro modelos dbt, testes de qualidade, catálogo e CI com GitHub Actions.

Resultado e evidência

Carga real em 29/10/2026: 75 observações históricas de 2022–2024, quatro modelos e 16 testes dbt aprovados; duração completa de 3min31s.

Escopo da demonstração

A carga substitui o snapshot histórico 2022–2024. O cron diário às 08h de São Paulo usa federação WIF sem chaves; uma execução automática por push foi validada em 02/11/2026. Ver histórico e evidência ↗ Na auditoria de 02/11/2026 às 11h38 (São Paulo), não havia execuções com evento schedule: a rotina diária ainda não foi comprovada. Os dados têm expiração; falhas prolongadas ou cron desativado interrompem a renovação.

Saber qual processo rodou, quando terminou e o que aconteceu em caso de falha.

Explorar projeto ↗Monitor demonstrativo no GitHub ↗
Arquitetura, competências e resultados
n8n / interface → API → fila → processo Python → SQLite e logs

O que a implementação demonstra

  • Disparos manuais e do n8n passam por uma fila compartilhada.
  • Histórico persistente com status, horários e resultado do processo.
  • Consulta de logs, timeout e solicitação de cancelamento no sistema original.

Resultado e evidência

O executor foi configurado para um job por vez e limite de 20 jobs na fila/ativos. São limites de configuração, não throughput medido.

Escopo da demonstração

O laboratório público demonstra persistência e leitura de histórico; não oferece disparo remoto, fila ou cancelamento. O executor original é local.

Orquestração com Apache Airflow

Cinco DAGs para ingestões individuais e um fluxo completo de Huggy, Zoho Bigin e Meta Ads até snapshot e build dbt.

Huggy / negócios Zoho / Meta → histórico Zoho → dbt snapshot → dbt build

A DAG completa tem seis tarefas. Correções locais incluem dbt isolado na imagem, montagem do projeto nos containers e configuração explícita de banco e usuário.

Validação operacional pendente: sintaxe e verificações locais passaram; reconstrução dos serviços e execução no scheduler/CeleryExecutor ainda não realizadas. As falhas antigas do executor não foram revalidadas.
